## Hostile-review rule

File count is not the success criterion.

A documentation, archive, research, state, or business-design repository can be functionally populated without executable code. Conversely, an executable repository is not considered healthy merely because it has many files.

The review therefore checks the repository against its own declared purpose and rejects these shortcuts:

- treating an intentionally documentation-first repository as empty;
- treating a historical/archive repository as a current runtime;
- treating an open PR as canonical because it is newer;
- treating branch names, old exact heads, old provider observations, or old review receipts as self-updating currentness;
- treating source presence or green CI as installation/deployment/runtime effect;
- replacing correct repo-specific licensing language with a portfolio-wide assumption.
